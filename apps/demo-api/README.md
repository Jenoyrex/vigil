# Vigil demo API

The backend of the public **Live Demo**: a Cloudflare Worker + D1 database that
serves the same `/v1` API contract the dashboard uses, on Cloudflare's free
plan (no card, no billing account). The existing Netlify dashboard is pointed
at it with two environment variables; the production architecture
(`apps/api`, PostgreSQL, ClickHouse, `services/worker`) is untouched. Design:
[ADR 009](../../docs/decisions/009-public-demo-architecture.md).

It is a standalone npm package, deliberately **not** part of the pnpm
workspace, so the dashboard's Netlify build and the production CI never
install Wrangler.

## What it implements

| Area | Endpoints |
|---|---|
| Auth | `POST /v1/auth/signup`, `POST /v1/auth/login`, `GET /v1/auth/session`, `POST /v1/auth/logout` |
| Workspace | `GET /v1/me`, `POST /v1/organizations`, `POST /v1/organizations/{id}/projects`, `GET`/`POST /v1/projects/{id}/api-keys`, `POST /v1/projects/{id}/api-keys/{key_id}/revoke` |
| Traces | `POST /v1/traces`, `GET /v1/traces`, `GET /v1/traces/{trace_id}`, `GET /v1/traces/{trace_id}/spans/{span_id}` |
| Evaluation | `GET /v1/evaluations/configs`, `GET`/`PUT /v1/evaluations/configs/{name}`, `GET /v1/evaluations/jobs`, `GET /v1/traces/{trace_id}/spans/{span_id}/evaluations` |
| Analytics | `GET /v1/analytics/spans`, `GET /v1/analytics/llm-usage` |

Response shapes are typed with the dashboard's own `lib/api/types.ts` and
`workspaceTypes.ts`; `test/contract.test.ts` fails to typecheck if they drift.

## How it differs from production

| Production | Demo |
|---|---|
| PostgreSQL + ClickHouse | One D1 (SQLite) database, `migrations/0001_init.sql` |
| Poller + worker evaluate asynchronously | The TF-IDF `relevance` evaluator runs during `POST /v1/traces` (up to 25 spans / 128 KiB of text per request; the rest are recorded as `dead_letter` with the reason) |
| scrypt password hashing | PBKDF2-SHA256, 8,000 iterations (fits the 10 ms CPU budget) — demo accounts only |
| `relevance_embedding` (BGE) | Rejected with a 422 explaining it is not in the demo |
| 10 MiB request bodies | 256 KiB |
| — | Per-IP / per-key rate limits, per-project data caps, 7-day telemetry retention, 30-day inactive-account cleanup (`src/config.ts`) |

Parity with production is tested against fixtures generated by running the
production Python code (`scripts/generate_parity_fixtures.py`): the TF-IDF
scores and explanations, ingestion truncation and formatting, pydantic
validation errors, and deterministic sampling.

## Develop

```sh
cd apps/demo-api
npm ci
npm run typecheck
npm test            # runs inside workerd against a real local D1
npm run dev         # local Worker on http://localhost:8787 (run db:migrate:local first)
```

## Deploy (one time)

Requires a free Cloudflare account; nothing here needs a card.

```sh
cd apps/demo-api
npx wrangler login
npx wrangler d1 create vigil-demo          # copy the printed database_id into wrangler.jsonc
npm run db:migrate:remote
npx wrangler secret put DASHBOARD_CLIENT_IP_TOKEN   # a long random string
npm run deploy                              # prints https://vigil-demo-api.<subdomain>.workers.dev
```

Then set these on the Netlify site (Site configuration → Environment
variables) and redeploy the dashboard:

| Variable | Value |
|---|---|
| `VIGIL_API_BASE_URL` | the Worker URL |
| `VIGIL_PUBLIC_API_BASE_URL` | the Worker URL (shown to SDK users on the Connect page) |
| `VIGIL_API_DASHBOARD_CLIENT_IP_TOKEN` | the same value as the Worker's `DASHBOARD_CLIENT_IP_TOKEN` |
| `VIGIL_DEMO_MODE` | `true` (shows the demo-only password notice on the signup page) |

Without the shared client-IP token, every dashboard user shares the
dashboard server's IP for signup/login rate limiting.

After deploying, check real CPU time per request in the Cloudflare dashboard
(Workers → vigil-demo-api → Observability). Signup/login are the heaviest
requests; if they approach 10 ms, lower `PBKDF2_ITERATIONS` in
`src/security.ts` (existing hashes keep their stored iteration count).

## Re-generating parity fixtures

After changing the production evaluator, ingestion, or request schemas:

```sh
services/worker/.venv/Scripts/python.exe apps/demo-api/scripts/generate_parity_fixtures.py relevance
VIGIL_API_INTERNAL_SERVICE_TOKEN=x apps/api/.venv/Scripts/python.exe apps/demo-api/scripts/generate_parity_fixtures.py api
```
